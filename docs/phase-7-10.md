# Targets, observability, hardening and deployment

Target registration distinguishes GROUP and CHANNEL and starts UNVERIFIED. Declared authorization is recorded but does not grant UI permission. Target references and invitation links are encrypted. Canonical HMAC identities deduplicate @username and its t.me URL form. Invite-link creation and join-request moderation return OPERATION_UNSUPPORTED pending verified UI capabilities. No member scraping, unsolicited adding or account rotation is implemented.

Operational APIs provide paginated jobs, cooperative cancellation, real PostgreSQL aggregates, worker heartbeats, administrator-only audit entries, allowlisted settings and Prometheus-compatible metrics. OTel manual HTTP spans include method/status and a trace ID, without submitted values. Set OTEL_EXPORTER_OTLP_TRACES_ENDPOINT to export; no collector is contacted by default. The current setup is not a complete distributed tracing/alerting stack.

WebSocket /events validates exact origin and hashed session cookie before upgrading, caps 100 connections, revalidates sessions every five seconds, restricts payload size and closes client writes. Events are versioned identifier-only resync notifications; REST remains authoritative. Slow-client buffers are bounded. The panel retries connection three times then retains periodic REST refresh. Behind nginx /events is proxied to the API; local Next-only development can set NEXT_PUBLIC_WS_URL=ws://localhost:3001/events at web build time.

Hardening includes a bounded Argon2 verification pool, distributed API/login limits, input/body limits, isolated XLSX parsing, secure cookies/CSRF/origin checks, nonce/AAD encryption, no secret-bearing logs, durable unknown-state recovery, authenticated metrics, non-root images and production Chromium sandbox. Cleanup defaults to dry-run: npm run cleanup. CLEANUP_APPLY=true applies the configured audit retention (7–365 days, default 90) and deletes expired admin sessions. Browser profile deletion, backup/key retention and large exports require additional operational procedures. The local DB benchmark inserts 500 jobs and reads a first page; it provides no browser/account capacity guarantee.

Production Compose and multi-stage Dockerfile provide a migration stage, production dependencies, non-root runtime, private PostgreSQL/Redis, encrypted profile archives, a tmpfs profile runtime, resource limits and a TLS nginx proxy. Docker is unavailable locally, so image build, container sandbox/seccomp, tmpfs, proxy/TLS and production restore drills are unverified. A separate real local PostgreSQL dump/restore drill did pass, including encrypted fixture recovery. Supply a valid HTTPS APP_ORIGIN, a least-privilege APP_DATABASE_URL and existing certificate directory TLS_CERT_DIR, then run docker compose -f docker-compose.production.yml config before building. Disable host swap for production profile tmpfs. Do not enable mutations as part of initial deployment.
